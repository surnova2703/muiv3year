# Текст для защиты диплома

## Глоссарий (на случай вопросов)

- **Метаданные** — всё про статью, кроме самого текста: название, авторы, год, журнал, тематики
- **OpenAlex** — бесплатный открытый каталог, 250+ млн научных работ
- **API** — способ запросить данные у внешнего сервиса по HTTP
- **DOI** — уникальный идентификатор статьи вида 10.XXXX/...
- **Аффилиация** — организация автора на момент публикации
- **Геокодирование** — получить координаты по названию места
- **Граф** — узлы и рёбра между ними
- **PostgreSQL** — реляционная СУБД, открытый исходный код
- **Фасетная фильтрация** — фильтры связаны между собой: выбор в одном сужает варианты в других
- **Балл сходства (score)** — взвешенная сумма пересечений множеств метаданных: авторы ×4, темы ×3, ключевые слова ×2, аффилиации ×2, журнал +2. score = 0 — статья не показывается
- **Режим отображения** — какие типы узлов и связей видны на графе одновременно
- **ER-диаграмма** — схема таблиц БД и связей между ними
- **РИНЦ / eLibrary** — российский индекс научного цитирования, закрытая платная база, публичного API нет
- **Cursor pagination** — постраничный обход через курсор, не по номеру страницы; надёжен при больших объёмах
- **gzip** — сжатие данных; ответы API сжимаются в 5–10 раз

## Слайд 2 — Актуальность (40–50 секунд)

Сегодня в открытом доступе больше 250 миллионов научных работ, и их объём удваивается каждые девять лет.

При таком масштабе традиционный поиск по ключевым словам помогает найти конкретную статью, но не отвечает на более широкие вопросы: кто с кем сотрудничает, из каких стран приходят исследования по теме, как со временем менялась тематика.

Карта и граф дают другой взгляд на те же данные — превращают тысячи строк метаданных в наглядный научный ландшафт. В нашей системе — 9 994 публикации, 80,8% из них с геокоординатами.

## Слайд 4 — Почему публикации после 2020 хуже представлены в базах? (30–40 секунд)

Спад объясняется четырьмя факторами одновременно.

Санкции 2022 года: Scopus и Web of Science остановили индексацию российских журналов, около 500 изданий удалено из Scopus.

Задержка OpenAlex: новые статьи появляются в каталоге через 6–18 месяцев, поэтому данные за 2023–2024 заведомо неполные.

Уход в отечественные базы: часть журналов переориентировалась на eLIBRARY и РИНЦ, которые с OpenAlex не связаны.

Фрагментация аффилиаций: авторы меняют или не указывают российскую принадлежность, идентификаторы организаций пропадают из метаданных.

Цель: разработать веб-приложение для анализа и интерактивной визуализации научных публикаций на основе открытых метаданных.

Нефункциональные: локальная работа без интернета, лимит 70 статей в графе и 200 в списке, без внешних JS-зависимостей, gzip-сжатие ответов в 5–10 раз.

## Слайд 8 — Обзор существующих решений (40–50 секунд)

Перед разработкой я изучила девять инструментов.

VOSviewer и CiteSpace мощные, но требуют установки и работают только с WoS и Scopus — без поиска похожих. Connected Papers строит граф для одной статьи, без карты. Bibliometrix работает с OpenAlex, но требует знания R. Lens.org — большая база, но нет графа. ResearchRabbit, Inciteful, Litmaps — современные веб-сервисы, работают с 1–2 стартовыми статьями и не дают карту с координатами.

Ни один не объединяет карту, граф, фасетные фильтры и поиск похожих. Полная сравнительная таблица — на слайде 19.

## Слайд 9 — Архитектура системы (40–50 секунд)

Система состоит из четырёх слоёв. Скрипт import.py загружает данные из OpenAlex и сохраняет в article_data.json. Затем данные переносятся в PostgreSQL — 7 таблиц, 9 994 публикации. Python-сервер openalex_server.py отдаёт REST API с gzip-сжатием. Браузерный интерфейс VKR1.html показывает карту, граф и фильтры.

## Слайд 10 — Обоснование выбора технологий (30–40 секунд)

Python со стандартной библиотекой — не требует Node.js, широкая экосистема для работы с данными. PostgreSQL — JOIN-запросы для нормализованной схемы, надёжные транзакции и savepoint-ы. Plotly — встроенные мировые карты, интерактивность без дополнительного сервера. SVG вместо D3 — граф в браузере без зависимостей: D3 и Cytoscape требуют npm или лицензии. OpenAlex — бесплатный источник с cursor pagination без ограничений.

## Слайд 11 — База данных — ER-диаграмма (30–40 секунд)

База — семь таблиц. Журналы и публикации — один ко многим. Публикации и авторы — многие ко многим. Аффилиации хранятся с широтой и долготой и привязаны к авторам. Тематики и ключевые слова — в отдельных таблицах, связанных с публикациями.

---

## Слайд 12 — Загрузка данных: import.py (40–50 секунд)

Скрипт обходит OpenAlex через cursor pagination — батчами по 200 публикаций. Используется потоковый парсинг через ijson: JSON не загружается целиком в память. Savepoint-ы защищают транзакции от конфликтов ключей при дублирующихся DOI. Промежуточный кэш article_data.json позволяет перезапустить загрузку без повторных запросов к API.

Результат: 9 994 публикации, около 50 000 строк в publication_authors, 30 000 в publication_topics.

---

## Слайд 13 — Географическая привязка (40–50 секунд)

Геокодирование — три этапа. Сначала организации сортируются по числу зависимых публикаций — первыми обрабатываются те, что разблокируют наибольшее число записей без координат.

Второй этап: запрос координат по идентификатору организации через API OpenAlex батчами по 100. Это дало 78%.

Третий этап: для аффилиаций без идентификатора — геокодирование по строке названия через Photon от OpenStreetMap. Скрипт пробует полное название, потом сокращает по запятым. Добавило ещё 2,8%.

Итого: 80,8% при пороге 75%.

## Слайд 14 — Граф связей (40–50 секунд)

К графу было несколько требований: работать в браузере без дополнительных запросов, не зависать при 70+ узлах, поддерживать пять режимов и показывать рёбра без пересечений.

Для этого выбрана колоночная раскладка: каждый тип сущности — в своей вертикальной колонке, рёбра — кривые Безье. Физической симуляции нет намеренно: force-directed при 70+ узлах даёт хаотичную картину, а колонки читаемы при любом числе.

Пять режимов — разные срезы одних данных: полный граф, годы и журналы, только авторы, только аффилиации, похожие статьи. Переключение мгновенное — данные уже в браузере.

---

## Слайд 15 — Интерфейс: структура и детали (30–40 секунд)

Одностраничное приложение с тремя колонками: слева — фильтры и список, по центру — карта или граф, справа — детали статьи и похожие.

Фасетная фильтрация: выбор в одном фильтре сужает варианты в других, нулевых результатов не бывает. Аннотация и DOI загружаются лениво — только при клике. Тёмная тема через CSS-переменные — меняется мгновенно, сохраняется в localStorage.

---

## Слайд 16 — Поиск похожих статей (50–60 секунд)

При клике на статью система перебирает все остальные и для каждой пары вычисляет пересечение множеств: авторов, тем, ключевых слов и аффилиаций.

Балл сходства — взвешенная сумма размеров этих пересечений: общие авторы дают ×4, общие темы — ×3, общие ключевые слова и аффилиации — ×2, одинаковый журнал — +2.

Авторы получили наибольший вес, потому что один человек работает в одной предметной области. Темы из OpenAlex — широкие классификаторы, поэтому их вес выше ключевых слов.

Перед сравнением строки приводятся к нижнему регистру: «MIT» и «mit» считаются одним значением. Статьи с нулевым баллом не показываются.

Результат — ранжированный список в правой панели и режим «Похожие статьи» на графе.

## Возможные вопросы комиссии

**— Почему PostgreSQL, а не SQLite или MongoDB?**
Жёсткие реляционные связи: один журнал — много статей, одна статья — много авторов. Нужны JOIN-запросы. SQLite не тянет параллельные запросы. MongoDB не даёт преимуществ — данные структурированные.

**— Почему не D3 или Cytoscape для графа?**
Force-directed при 70+ узлах даёт хаотичное расположение. Я сделала колоночную раскладку — предсказуемую при любом числе узлов. Это требовало кастомного рендеринга, D3 и Cytoscape ещё требуют npm или лицензии.

**— Почему OpenAlex, а не РИНЦ / eLibrary?**
РИНЦ — закрытая платная база, публичного API нет. eLibrary даёт доступ только по договору. OpenAlex бесплатный без регистрации, даёт аффилиации с идентификаторами и cursor pagination — это принципиально для геокодирования.

**— Чем отличаетесь от Connected Papers?**
Connected Papers строит граф вокруг одной статьи по цитированиям и даёт 5 графов в месяц бесплатно. Моя система работает со всем набором из ~10 000 статей, добавляет географическую карту, фасетные фильтры и считает сходство по пересечению пяти множеств — не только по цитированиям.

**— Почему 80%, а не 100% с координатами?**
Часть аффилиаций записана произвольной строкой без города или университета — например «Department of Physics». Геокодер тут бессилен. 19,2% — именно такие случаи.

**— Как масштабируется при большем числе статей?**
Граф ограничен 70 статьями для читаемости. Карта и список работают с полным набором через пагинацию. Больше 10 000 — потребуется серверный рендеринг графа, это включено в направления развития.

**— Как оцениваете качество алгоритма поиска похожих?**
Алгоритм работает по метаданным, не по тексту — считается мгновенно в браузере. Ограничение: если два автора из разных областей публикуются вместе, алгоритм посчитает их похожими. Веса подобраны эмпирически на реальных данных.

**— Что такое режим отображения?**
Какие типы узлов и связей видны одновременно. Пять режимов: полный граф, годы и журналы, только авторы, только аффилиации, похожие статьи. Переключение мгновенное — данные уже в браузере.

**— Зачем savepoint-ы при загрузке?**
Иногда два объекта из OpenAlex ссылаются на один DOI. Без savepoint-а вся транзакция откатывается при конфликте ключей. Savepoint позволяет пропустить дубль и продолжить загрузку остальных записей.

**— Почему Photon, а не Google Maps API для геокодирования?**
Google Maps платный. Photon основан на OpenStreetMap, бесплатный, работает локально без ключей. Для наших задач точность достаточная — нужны координаты города или организации, не точный адрес.
