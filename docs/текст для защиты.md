# Текст для защиты диплома

## Глоссарий (на случай вопросов)

- **Метаданные** — всё про статью, кроме самого текста: название, авторы, год, журнал, тематики
- **OpenAlex** — бесплатный открытый каталог, 250+ млн научных работ
- **API** — способ запросить данные у внешнего сервиса по HTTP
- **DOI** — уникальный идентификатор статьи вида 10.XXXX/...
- **Аффилиация** — организация автора на момент публикации
- **Геокодирование** — получить координаты по названию места
- **Граф** — узлы и рёбра между ними
- **PostgreSQL** — реляционная СУБД, открытый исходный код
- **Фасетная фильтрация** — фильтры связаны между собой: выбор в одном сужает варианты в других
- **Балл сходства** — число, показывающее насколько похожи две статьи по метаданным
- **Режим отображения** — какие типы узлов и связей сейчас видны на графе
- **ER-диаграмма** — схема таблиц БД и связей между ними

## Слайд 1 — Титульный (10–15 секунд)

Добрый день. Тема моей работы — «Визуализация науки на основе метаданных публикаций и журналов». Я разработала веб-приложение, которое позволяет исследовать научные публикации через интерактивную карту и граф связей.

---

## Слайд 2 — Актуальность (40–50 секунд)

Сегодня в открытом доступе больше 250 миллионов научных работ. По данным Борнманна и Мутца (2014), их число удваивалось примерно каждые девять лет — это темп роста около 8–9% в год за период 1980–2012.

При таком объёме поиск по ключевым словам помогает найти конкретную статью, но не даёт ответа на более широкие вопросы: кто с кем сотрудничает, откуда приходят исследования по теме, как со временем менялась тематика.

Карта и граф дают другой взгляд на те же данные — превращают тысячи строк в понятную картину.

---

## Слайд 3 — Динамика публикационной активности (20–30 секунд)

На графике — публикационная активность по годам из нашей базы. Пик — 2009–2010 годы. После 2020 видим спад, но это не падение науки — новые статьи попадают в OpenAlex с задержкой, плюс ряд других причин, о которых следующий слайд.

---

## Слайд 4 — Почему публикации после 2020 хуже представлены в базах? (30–40 секунд)

Спад на графике объясняется четырьмя вещами сразу.

Санкции 2022 года — Scopus и Web of Science остановили индексацию российских журналов, около 500 изданий было удалено из Scopus.

Задержка OpenAlex — новые статьи появляются в каталоге через 6–18 месяцев после публикации, так что данные за 2023–2024 объективно неполные.

Уход в РИНЦ — часть журналов переориентировалась на eLIBRARY, который с OpenAlex не связан.

Фрагментация аффилиаций — авторы начали скрывать или не указывать российскую принадлежность, идентификаторы организаций пропадают из метаданных.

## Слайд 5 — Цель и задачи (50–60 секунд)

Объект — метаданные научных публикаций в открытых каталогах. Предмет — методы их визуализации: географическая карта аффилиаций и граф связей.

Цель: разработать веб-приложение для анализа и интерактивной визуализации научных публикаций на основе открытых метаданных.

Задачи: загрузить данные из OpenAlex, спроектировать базу, геокодировать аффилиации, реализовать карту, граф, REST API и браузерный интерфейс с фасетными фильтрами.

Ориентиры по качеству я поставила такие: покрытие геокодирования минимум 75%, граф не зависает в браузере, фильтры не дают пустых результатов.

---

## Слайд 6 — Обзор существующих решений (50–60 секунд)

Перед разработкой я посмотрела девять существующих инструментов: VOSviewer, CiteSpace, Connected Papers, Bibliometrix, Gephi, Lens.org, ResearchRabbit, Inciteful, Litmaps.

VOSviewer и CiteSpace мощные, но нужна установка и нет алгоритма похожих статей. Connected Papers строит граф похожих, но только для одной статьи и без карты. Bibliometrix работает с OpenAlex, но требует знания R. ResearchRabbit, Inciteful, Litmaps — современные браузерные сервисы, но ни один не совмещает карту с точными координатами и граф.

В итоге ни один не даёт сразу всё: карту, граф, фасетные фильтры и поиск похожих — поэтому я делала свою систему.

---

## Слайд 7 — Архитектура системы (50–60 секунд)

Система состоит из пяти частей. Скрипт import.py загружает данные из OpenAlex и сохраняет в JSON. Следующий скрипт переносит их в PostgreSQL. Два скрипта геокодирования добавляют координаты. Сервер на Python отдаёт REST API. Браузер показывает карту, граф и фильтры.

По технологиям: PostgreSQL — потому что между сущностями чёткие реляционные связи, нужны JOIN-запросы. Plotly — встроенная поддержка карт и интерактивности. SVG без библиотек — потому что нужна колоночная раскладка, а не хаотичная. OpenAlex — единственный бесплатный источник с аффилиациями и пакетным API организаций.

---

## Слайд 8 — База данных (40–50 секунд)

База данных — семь таблиц: журналы, публикации, авторы, аффилиации с координатами, и три таблицы связей.

Настройки подключения в отдельном pg_config.py. Там обязательно client_encoding: utf8 — без него на Windows PostgreSQL возвращает ошибки в cp1251 и Python падает.

При загрузке использовались savepoint-ы — иногда два объекта из OpenAlex ссылались на один DOI. В итоге все 9 994 публикации загружены без потерь.

---

## Слайд 9 — ER-диаграмма базы данных (20–30 секунд)

На схеме видны связи между таблицами. Журналы к публикациям — один ко многим. Публикации и авторы — многие ко многим через publication_authors. Аффилиации хранятся с координатами и привязаны к авторам. Тематики и ключевые слова тоже отдельными таблицами.

---

## Слайд 10 — Географическая привязка (50–60 секунд)

Геокодирование в два шага. Сначала — организации с идентификатором OpenAlex, координаты запрашиваются через API батчами по 100. Это дало 78%.

Оставшиеся 22% — аффилиации только строкой названия. Для них написан скрипт с геокодером Photon от Komoot. Скрипт пробует полное название, потом сокращает строку по запятым, пока не получит результат. Важная деталь — Photon отдаёт координаты в формате longitude/latitude, а не наоборот, поэтому при сохранении переставляю вручную.

Обрабатываются в первую очередь организации, которые закрывают максимум публикаций без координат. Итого: 80,8%.

---

## Слайд 11 — Граф связей (50–60 секунд)

Граф рисуется в браузере в SVG, без внешних библиотек. Данные уже загружены, дополнительных запросов к серверу нет. Из каждой статьи берутся год, журнал, авторы и аффилиации — из них строятся узлы и рёбра.

Для размещения узлов — колоночная раскладка: каждый тип сущности в своей вертикальной колонке. Рёбра — кривые Безье. Физической симуляции нет намеренно — при 70+ узлах force-directed даёт хаотичную картину, а колонки читаемы при любом числе.

Доступно пять режимов. Режим отображения — это какие типы узлов и связей видны одновременно. Например, полный граф показывает всё: год → журнал → статья → автор → аффилиация. Режим «Авторы» убирает лишнее, оставляет только статья–автор. Режим «Похожие статьи» соединяет статьи с высоким баллом сходства.

---

## Слайд 12 — Поиск похожих статей (50–60 секунд)

При клике на статью система перебирает все остальные публикации и считает балл сходства. Учитываются пять признаков: общие авторы — вес 4, общие темы — вес 3, общие ключевые слова и аффилиации — вес 2, одинаковый журнал — плюс 2.

Авторы получили наибольший вес, потому что один человек работает в одной предметной области — его статьи содержательно близки. Темы из OpenAlex — широкие классификаторы, поэтому вес выше, чем у ключевых слов.

Перед сравнением все строки приводятся к нижнему регистру — иначе «MIT» и «mit» считались бы разными.

Результат виден в правой панели как ранжированный список с объяснением, и в режиме «Похожие статьи» в графе.

---

## Слайд 13 — Веб-интерфейс (40–50 секунд)

Интерфейс — одностраничное приложение с тремя колонками. Слева — фильтры и список статей. По центру — карта или граф. Справа — детали выбранной статьи и похожие.

Фильтры работают в связке: выбор в одном ограничивает варианты в других. Это фасетная фильтрация — она исключает ситуацию с нулевым результатом.

Есть светлая и тёмная тема. Переключение сохраняется в localStorage, все цвета через CSS-переменные — меняется мгновенно.

## Слайд 14 — Результаты (40–50 секунд)

Все задачи выполнены. Загружено 9 994 публикации из OpenAlex. База данных — 7 таблиц PostgreSQL. Геокодировано 80,8% публикаций при пороге 75%. Граф с пятью режимами отображения. Алгоритм поиска похожих статей по пяти признакам.

Система переводит плоский список статей в два визуальных представления — карту с географией и граф с авторскими и тематическими связями. По сравнению с аналогами — всё это в одной браузерной среде, без установки.

## Возможные вопросы комиссии

**— Почему PostgreSQL, а не SQLite или MongoDB?**
Между сущностями жёсткие реляционные связи: один журнал — много статей, одна статья — много авторов. Нужны сложные JOIN-запросы для фильтрации. SQLite не тянет параллельные запросы, MongoDB тут не даёт преимуществ — данные структурированные.

**— Почему не D3 или Cytoscape для графа?**
Стандартный force-directed при 70+ узлах даёт хаотичное расположение, с ним сложно работать. Я сделала колоночную раскладку — предсказуемую при любом числе узлов. Это требовало кастомного рендеринга, не библиотечного.

**— Чем отличаетесь от Connected Papers?**
Connected Papers строит граф вокруг одной статьи по цитированиям и даёт 5 графов в месяц бесплатно. Моя система работает со всем набором из ~10 000 статей, добавляет географическую карту, фасетные фильтры и считает сходство по пяти признакам — не только по цитированиям.

**— Почему 80%, а не 100% с координатами?**
Часть аффилиаций в OpenAlex записана произвольной строкой — например, «Department of Physics» без названия города или университета. Геокодер тут бессилен. 19,2% — это именно такие случаи.

**— Как масштабируется при большем числе статей?**
Граф ограничен 70 статьями для читаемости. Карта и список работают с полным набором через пагинацию. Если нужно больше 10 000 — потребуется серверный рендеринг графа.

**— Почему OpenAlex, а не Semantic Scholar или Crossref?**
OpenAlex бесплатный без регистрации, даёт аффилиации с идентификаторами, cursor pagination для надёжной выгрузки и отдельный эндпоинт /institutions для пакетного запроса координат — это ключевое для геокодирования.

**— Как оцениваете качество алгоритма поиска похожих?**
Алгоритм работает по метаданным, не по тексту статьи — поэтому быстро считается прямо в браузере, без дополнительных запросов. Ограничение — если два автора из разных областей случайно пересекаются, алгоритм их посчитает похожими. Веса подобраны эмпирически на реальных данных.

**— Что нового по сравнению с ResearchRabbit, Inciteful, Litmaps?**
Они работают с одной-двумя стартовыми статьями и строят граф по цитированиям. Моя система работает с заранее загруженным набором — исследуешь тематический и географический ландшафт всей предметной области сразу, не ищешь похожее к одной статье.

**— Что такое режим отображения в графе?**
Какие типы узлов и связей видны одновременно. Всего пять: полный граф, годы и журналы, только авторы, только аффилиации, похожие статьи. Сделано для читаемости — при всех узлах одновременно граф перегружен. Переключение мгновенное, данные уже в браузере.
