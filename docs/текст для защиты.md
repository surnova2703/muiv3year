# Текст для защиты диплома

## Глоссарий (на случай вопросов)

- **Метаданные** — всё про статью, кроме самого текста: название, авторы, год, журнал, тематики
- **OpenAlex** — бесплатный открытый каталог, 250+ млн научных работ
- **API** — способ запросить данные у внешнего сервиса по HTTP
- **DOI** — уникальный идентификатор статьи вида 10.XXXX/...
- **Аффилиация** — организация автора на момент публикации
- **Геокодирование** — получить координаты по названию места
- **Граф** — узлы и рёбра между ними
- **PostgreSQL** — реляционная СУБД, открытый исходный код
- **Фасетная фильтрация** — фильтры связаны между собой: выбор в одном сужает варианты в других
- **Балл сходства (score)** — целое число, показывающее степень близости двух публикаций по метаданным. Считается как взвешенная сумма размеров пересечений множеств: каждый общий автор даёт +4, общая тема — +3, общее ключевое слово или аффилиация — +2, одинаковый журнал — +2. Чем выше балл, тем содержательно ближе статьи. Статьи с нулевым баллом в результаты не попадают
- **Режим отображения** — какие типы узлов и связей сейчас видны на графе
- **ER-диаграмма** — схема таблиц БД и связей между ними
- **РИНЦ / eLibrary** — российский индекс научного цитирования, закрытая платная база, API публично недоступен

## Слайд 1 — Титульный (10–15 секунд)

Добрый день. Тема моей работы — «Визуализация науки на основе метаданных публикаций и журналов». Я разработала веб-приложение, которое позволяет исследовать научные публикации через интерактивную карту и граф связей.

---

## Слайд 2 — Актуальность (40–50 секунд)

Сегодня в открытом доступе больше 250 миллионов научных работ. По данным Борнманна и Мутца (2014), их число удваивалось примерно каждые девять лет — это темп роста около 8–9% в год за период 1980–2012.

При таком объёме поиск по ключевым словам помогает найти конкретную статью, но не даёт ответа на более широкие вопросы: кто с кем сотрудничает, откуда приходят исследования по теме, как со временем менялась тематика.

Карта и граф дают другой взгляд на те же данные — превращают тысячи строк в понятную картину.

---

## Слайд 3 — Динамика публикационной активности (20–30 секунд)

На графике — публикационная активность по годам из нашей базы. Пик — 2009–2010 годы. После 2020 видим спад, но это не падение науки — новые статьи попадают в OpenAlex с задержкой, плюс ряд других причин, о которых следующий слайд.

---

## Слайд 4 — Почему публикации после 2020 хуже представлены в базах? (30–40 секунд)

Спад на графике объясняется четырьмя факторами.

Санкции 2022 года — Scopus и Web of Science остановили индексацию российских журналов, около 500 изданий было удалено из Scopus.

Задержка OpenAlex — новые статьи появляются в каталоге через 6–18 месяцев после публикации.

Уход в РИНЦ — часть журналов переориентировалась на eLIBRARY, который с OpenAlex не связан.

Фрагментация аффилиаций — авторы начали скрывать или не указывать российскую принадлежность.

## Слайд 5 — Цель и задачи (50–60 секунд)

Объект — метаданные научных публикаций в открытых каталогах. Предмет — методы их визуализации: географическая карта аффилиаций и граф связей.

Цель: разработать веб-приложение для анализа и интерактивной визуализации научных публикаций на основе открытых метаданных.

Задачи: загрузить данные из OpenAlex, спроектировать базу, геокодировать аффилиации тремя этапами, реализовать карту, граф, REST API и браузерный интерфейс с фасетными фильтрами.

Ориентиры по качеству: покрытие геокодирования минимум 75%, граф не зависает в браузере, фильтры не дают пустых результатов.

## Слайд 6 — Научная новизна и практическая значимость (30–40 секунд)

Научная новизна — алгоритм многоуровневого геокодирования с приоритизацией аффилиаций по частоте упоминания, и алгоритм поиска похожих статей по пересечению множеств метаданных.

Практическая значимость — система работает полностью в браузере, без установки, на открытых данных. Исследователь видит географию и сеть связей всей тематической области сразу, не ищет похожее к одной статье.

Функциональные требования: загрузка из OpenAlex, хранение в БД, геокодирование, карта, граф с пятью режимами, REST API, фасетные фильтры.

Нефункциональные: работа в браузере без установки, покрытие координатами ≥ 75%, граф читаем при 70 статьях одновременно.

## Слайд 8 — Обзор существующих решений (40–50 секунд)

Перед разработкой я изучила девять инструментов.

VOSviewer и CiteSpace мощные, но требуют установки, работают только с WoS/Scopus и не ищут похожие статьи. Connected Papers строит граф похожих, но только для одной статьи и без карты. Bibliometrix работает с OpenAlex, но требует знания R. Lens.org — большая база, но нет графа связей. ResearchRabbit, Inciteful, Litmaps — современные веб-сервисы, но работают с 1–2 стартовыми статьями и не дают карту с координатами.

Ни один не объединяет карту, граф, фасетные фильтры и поиск похожих в одном браузерном приложении. Полная сравнительная таблица — на последнем слайде.

## Слайд 9 — Архитектура системы (40–50 секунд)

Система состоит из пяти частей. Скрипт import.py загружает данные из OpenAlex и сохраняет в JSON. Следующий скрипт переносит их в PostgreSQL. Два скрипта геокодирования добавляют координаты. Сервер на Python отдаёт REST API. Браузер показывает карту, граф и фильтры.

---

## Слайд 10 — Обоснование выбора технологий (30–40 секунд)

PostgreSQL — потому что между сущностями чёткие реляционные связи, нужны JOIN-запросы. Plotly — встроенная поддержка карт и интерактивности без внешних зависимостей. Стандартная библиотека Python — сервер без фреймворков, чистый HTTP. OpenAlex — единственный бесплатный открытый источник с аффилиациями, пакетным API и cursor pagination.

---

## Слайд 11 — База данных — ER-диаграмма (30–40 секунд)

База — семь таблиц. Журналы и публикации — связь один ко многим. Публикации и авторы — многие ко многим через таблицу publication_authors. Аффилиации хранятся с координатами. Тематики и ключевые слова — в отдельных таблицах со своими связями.

При загрузке использовались savepoint-ы: иногда два объекта из OpenAlex ссылались на один DOI. Все 9 994 публикации загружены без потерь.

---

## Слайд 12 — Загрузка данных: import.py (30–40 секунд)

Скрипт обходит OpenAlex через cursor pagination — батчами по 200 публикаций. Каждая запись разворачивается в плоскую структуру и раскладывается по семи таблицам. Savepoint-ы защищают от дублирующихся DOI в OpenAlex. Промежуточный JSON-кэш позволяет перезапускать импорт без повторного обращения к API.

---

## Слайд 13 — Географическая привязка (50–60 секунд)

Геокодирование в три этапа. Сначала — аффилиации с идентификатором OpenAlex: координаты запрашиваются батчами по 100. Это дало 78%.

Второй этап — аффилиации только строкой названия: используется геокодер Photon от Komoot. Скрипт пробует полное название, потом сокращает строку по запятым, пока не получит результат. Photon отдаёт координаты в формате longitude/latitude — при сохранении переставляю вручную.

Обрабатываются в первую очередь организации, которые закрывают максимум публикаций без координат.

Итого: 80,8% при пороге 75%.

---

## Слайд 14 — Граф связей (40–50 секунд)

К графу было несколько требований: работать в браузере без серверных запросов, не зависать при 70+ узлах, поддерживать пять режимов отображения и показывать рёбра без пересечений.

Для этого выбрана колоночная раскладка: каждый тип сущности в своей вертикальной колонке, рёбра — кривые Безье. Физической симуляции нет намеренно — force-directed при 70+ узлах даёт хаотичную картину, а колонки читаемы при любом числе.

Пять режимов — это разные срезы одних данных: полный граф, годы и журналы, только авторы, только аффилиации, похожие статьи.

---

## Слайд 15 — Интерфейс: структура и детали (30–40 секунд)

Одностраничное приложение: три колонки. Слева — фильтры и список статей. По центру — карта или граф. Справа — детали выбранной статьи и похожие.

Фасетная фильтрация: выбор в одном фильтре сужает варианты в других — нулевых результатов не бывает. Аннотация и DOI загружаются лениво — только при клике. Тёмная тема через CSS-переменные, сохраняется в localStorage.

---

## Слайд 16 — Поиск похожих статей (50–60 секунд)

При клике на статью система перебирает все остальные публикации и для каждой пары вычисляет пересечение множеств: авторов, тем, ключевых слов и аффилиаций.

Балл сходства — взвешенная сумма размеров этих пересечений: общие авторы дают вес 4, общие темы — 3, общие ключевые слова и аффилиации — по 2, одинаковый журнал — ещё 2.

Авторы получили наибольший вес, потому что один человек работает в одной предметной области. Темы из OpenAlex — широкие классификаторы, поэтому их вес выше, чем у ключевых слов.

Перед сравнением все строки приводятся к нижнему регистру — «MIT» и «mit» считаются одним значением. Статьи с нулевым баллом не показываются.

Результат виден в правой панели как ранжированный список и в режиме «Похожие статьи» на графе.

## Возможные вопросы комиссии

**— Почему PostgreSQL, а не SQLite или MongoDB?**
Между сущностями жёсткие реляционные связи: один журнал — много статей, одна статья — много авторов. Нужны сложные JOIN-запросы для фильтрации. SQLite не тянет параллельные запросы, MongoDB тут не даёт преимуществ — данные структурированные.

**— Почему не D3 или Cytoscape для графа?**
Стандартный force-directed при 70+ узлах даёт хаотичное расположение, с ним сложно работать. Я сделала колоночную раскладку — предсказуемую при любом числе узлов. Это требовало кастомного рендеринга, не библиотечного.

**— Почему OpenAlex, а не РИНЦ / eLibrary?**
РИНЦ — закрытая платная база, публичного API нет. eLibrary предоставляет ограниченный доступ только через платную подписку или по договору. OpenAlex бесплатный без регистрации, даёт аффилиации с идентификаторами и cursor pagination для надёжной полной выгрузки — это принципиально для геокодирования.

**— Чем отличаетесь от Connected Papers?**
Connected Papers строит граф вокруг одной статьи по цитированиям и даёт 5 графов в месяц бесплатно. Моя система работает со всем набором из ~10 000 статей, добавляет географическую карту, фасетные фильтры и считает сходство по пересечению пяти множеств метаданных — не только по цитированиям.

**— Почему 80%, а не 100% с координатами?**
Часть аффилиаций в OpenAlex записана произвольной строкой — например, «Department of Physics» без названия города или университета. Геокодер тут бессилен. 19,2% — это именно такие случаи.

**— Как масштабируется при большем числе статей?**
Граф ограничен 70 статьями для читаемости. Карта и список работают с полным набором через пагинацию. Если нужно больше 10 000 — потребуется серверный рендеринг графа.

**— Как оцениваете качество алгоритма поиска похожих?**
Алгоритм работает по метаданным, не по тексту — поэтому считается мгновенно прямо в браузере. Ограничение: если два автора из разных областей случайно публикуются вместе, алгоритм их посчитает похожими. Веса подобраны эмпирически на реальных данных.

**— Что нового по сравнению с ResearchRabbit, Inciteful, Litmaps?**
Они работают с 1–2 стартовыми статьями и строят граф по цитированиям. Моя система работает с загруженным набором — исследуешь тематический и географический ландшафт всей предметной области сразу.

**— Что такое режим отображения в графе?**
Какие типы узлов и связей видны одновременно. Всего пять: полный граф, годы и журналы, только авторы, только аффилиации, похожие статьи. Переключение мгновенное, данные уже в браузере.
