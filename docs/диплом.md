# ВЫПУСКНАЯ КВАЛИФИКАЦИОННАЯ РАБОТА

## Визуализация науки на основе метаданных публикаций и журналов

---

## АННОТАЦИЯ

Работа посвящена разработке веб-приложения для анализа и визуализации научных публикаций по метаданным из открытых источников. В ходе работы выполнена автоматическая загрузка данных через API OpenAlex, спроектирована реляционная база данных PostgreSQL, выполнено геокодирование организаций авторов, реализованы интерактивная карта и граф связей, разработаны серверный API и браузерный интерфейс. Итогом стало работающее веб-приложение, позволяющее рассматривать набор научных публикаций как географическую карту организаций авторов и как граф связей между публикациями, авторами, журналами и темами.

**Ключевые слова:** визуализация данных, научные публикации, OpenAlex, PostgreSQL, геокодирование, граф связей, веб-приложение.

## ВВЕДЕНИЕ

### Актуальность

По данным каталога OpenAlex [1], в открытом доступе сейчас находится более 250 миллионов научных работ. Борнманн и Мутц показали, что в период 1980–2012 годов число публикаций удваивалось примерно каждые девять лет — около 8–9% в год [18]. При таком объёме привычный поиск по ключевым словам хорошо справляется с задачей «найти конкретную статью», но плохо подходит для вопросов на уровне области: кто с кем сотрудничает, откуда приходят исследования по теме, как она развивалась со временем.

Карта и граф дают другую точку зрения на те же данные. Метаданные публикации — название, авторы, их организации, год, журнал, тематические классификаторы — позволяют построить оба представления без доступа к полному тексту статьи. Именно это составляет основу данного проекта.

### Постановка задачи

**Объект исследования** — метаданные научных публикаций и журналов из открытых библиографических каталогов.

**Предмет исследования** — методы интерактивной визуализации этих метаданных: географическая карта аффилиаций авторов и граф связей между публикациями, авторами, журналами и организациями.

**Цель работы** — разработать веб-приложение для интерактивного анализа и визуализации научных публикаций на основе открытых метаданных.

Для достижения цели поставлены следующие задачи:
1. Загрузить метаданные публикаций из API OpenAlex.
2. Разработать реляционную базу данных PostgreSQL для их хранения.
3. Выполнить геокодирование организаций авторов.
4. Реализовать интерактивную карту с географией публикаций.
5. Реализовать граф связей: публикации — авторы — журналы — темы — аффилиации.
6. Разработать серверный API и веб-интерфейс.

Ориентиры качества заданы заранее: покрытие геокодирования — не менее 75%; граф отображается без зависания браузера при наборе до 70 статей; фасетные фильтры гарантируют отсутствие пустых выборок; алгоритм поиска похожих статей учитывает не менее трёх независимых признаков с обоснованными весами.

### Научная новизна

Разработанная система отличается от существующих инструментов тем, что совмещает в одной браузерной среде географическую карту с точными координатами организаций, граф структурных связей между публикациями в нескольких режимах отображения, фасетную фильтрацию и алгоритм поиска тематически близких статей, не основанный исключительно на цитировании. Ни один из рассмотренных в первой главе инструментов не предоставляет этого набора возможностей без установки дополнительного программного обеспечения.

### Практическая значимость

Система может применяться исследователями, аспирантами и редакторами журналов для быстрой навигации по тематическому и географическому ландшафту предметной области. Приложение запускается локально на любом компьютере с Python и PostgreSQL без дополнительных платных сервисов. Код открыт и допускает замену источника данных или расширение набора признаков алгоритма сходства.

## ГЛАВА I. ОБЗОР СУЩЕСТВУЮЩИХ РЕШЕНИЙ

Перед началом разработки был проведён анализ девяти существующих инструментов для библиометрического анализа и визуализации публикаций, актуальных на 2024–2025 год.

### 1.1. VOSviewer

VOSviewer [2] — бесплатная программа для построения и визуализации библиометрических сетей, разработанная Лейденским университетом (Нидерланды). Распространяется как настольное приложение для Windows, macOS и Linux.

**Визуализации:** сети соавторства, совместного цитирования, библиографического сочетания, совместного употребления ключевых слов; карты плотности и наложения. Поддерживает отображение географии сотрудничества по странам.

**Источники данных:** Web of Science, Scopus, PubMed, Dimensions, Semantic Scholar. Данные необходимо подготовить и экспортировать в поддерживаемом формате заранее — встроенного поиска нет.

**Ограничения:** отсутствует алгоритм поиска похожих статей; фильтрация ограничена; установка на компьютер обязательна; веб-версия требует сохранения данных в облаке.

### 1.2. CiteSpace

CiteSpace [3] — бесплатное Java-приложение для анализа тенденций и структурных паттернов в научной литературе, разработанное в Университете Дрексела (США).

**Визуализации:** сети цитирования с выделением всплесков активности, кластерная раскладка, карты географического сотрудничества по странам (экспорт в KML).

**Источники данных:** Web of Science, Scopus, Dimensions, Lens.org, PubMed.

**Ограничения:** требует Java Runtime Environment; нет алгоритма похожих статей; интерфейс перегружен настройками; отсутствует веб-версия.

### 1.3. Connected Papers

Connected Papers — веб-сервис для визуального исследования тематических связей между статьями. Базовый доступ бесплатный (5 графов в месяц), расширенный — от 6 долларов в месяц.

**Визуализации:** граф похожих статей, построенный на основе совместного цитирования и библиографического сочетания.

**Алгоритм схожести:** учитывает совместное цитирование и сближение ссылок, приоритет отдаётся статьям близкого года публикации. Граф строится вокруг одной выбранной статьи.

**Ограничения:** нет географической карты; одновременно анализируется только одна статья; нет фильтрации по авторам, аффилиациям или журналам.

### 1.4. Bibliometrix / Biblioshiny

Bibliometrix [4] — пакет для языка R с открытым исходным кодом (лицензия MIT), предназначенный для количественного анализа научной литературы. Biblioshiny — его веб-интерфейс на основе Shiny.

**Визуализации:** карты соавторства по странам, сети ключевых слов, тематические карты, плотностные карты аффилиаций.

**Источники данных:** Web of Science, Scopus, PubMed, OpenAlex, Lens.org, Dimensions.

**Ограничения:** требует установки R; нет поиска похожих статей; высокий порог вхождения без опыта программирования.

### 1.5. Gephi

Gephi [5] — бесплатная программа с открытым кодом для визуализации и анализа больших сетей. Поддерживает до 10 миллионов элементов.

**Визуализации:** сетевые графы с настраиваемой раскладкой, визуализация центральности, кластеризация.

**Ограничения:** данные необходимо предварительно подготовить в форматах GEXF, GraphML, CSV; нет встроенного подключения к источникам научных данных; нет географической карты; нет алгоритма схожести.

### 1.6. Lens.org

Lens.org — бесплатный веб-сервис для поиска и анализа научных публикаций и патентов (более 225 млн работ).

**Визуализации:** распределение публикаций по времени, топ-институтов, географическая карта по странам.

**Ограничения:** нет алгоритма поиска похожих статей; нет графа связей между публикациями и авторами; визуализация ограничена агрегированными диаграммами.

### 1.7. ResearchRabbit

ResearchRabbit — бесплатный веб-сервис (2020), позиционируемый как «Spotify для научных статей».

**Визуализации:** граф связей на основе совместного цитирования, временная шкала публикаций, кластеры авторов.

**Алгоритм схожести:** строится на анализе цитирований из базы Semantic Scholar. Интегрируется с Zotero.

**Ограничения:** нет географической карты; алгоритм работает только с цитированиями — новые работы без цитирований не учитываются.

### 1.8. Inciteful

Inciteful — бесплатный веб-инструмент (2021) для анализа связей на основе графа цитирований из OpenAlex.

**Визуализации:** граф цитирований вокруг одной или нескольких статей; рейтинги статей по PageRank.

**Ограничения:** нет географической карты; нет поиска по авторам и аффилиациям; граф строится только вокруг явных цитирований; нет фасетной фильтрации.

### 1.9. Litmaps

Litmaps — веб-сервис (2021, Новая Зеландия) для построения карт научной литературы с акцентом на временну́ю динамику цитирований. Freemium-модель.

**Визуализации:** карта цитирований вокруг одной или нескольких статей с временно́й осью.

**Источники данных:** Semantic Scholar (более 200 млн работ).

**Ограничения:** нет географической карты аффилиаций; нет фильтрации по авторам или организациям; граф строится только на основе явных цитирований.

### 1.12. Выводы из обзора

Каждый из рассмотренных инструментов решает отдельные задачи визуализации, однако ни один не сочетает одновременно все необходимые возможности. VOSviewer [2] и CiteSpace [3] мощны, но требуют установки и не имеют алгоритма похожих статей. Connected Papers обладает алгоритмом схожести, но работает только с одной статьёй за раз. Bibliometrix [4] интегрируется с OpenAlex, однако требует знания R. Lens.org предоставляет карту и фильтрацию, но ограничен агрегированными диаграммами.

Разработанная система занимает нишу, не закрытую существующими решениями: она объединяет в одном браузерном интерфейсе географическую карту с точными координатами организаций, граф связей с пятью режимами, фасетную фильтрацию и алгоритм поиска похожих статей по пяти признакам — без необходимости установки стороннего программного обеспечения.

## ГЛАВА II. ТРЕБОВАНИЯ К СИСТЕМЕ

### 2.1. Назначение системы

Система предназначена для интерактивного исследования массивов научных публикаций. Целевая аудитория — исследователи, аспиранты и специалисты, которым требуется быстро ориентироваться в большом количестве публикаций по теме, выявлять географию исследований и находить тематически близкие работы.

### 2.2. Функциональные требования

Система должна выполнять следующие функции:

- загружать метаданные публикаций из OpenAlex API и сохранять в локальную базу данных;
- отображать интерактивную карту с точками аффилиаций авторов;
- отображать граф связей публикация — автор — журнал — аффилиация в пяти режимах;
- предоставлять фасетную фильтрацию по году, журналу, автору и аффилиации;
- при выборе публикации вычислять и показывать список похожих статей с объяснением совпадений;
- поддерживать переключение между светлой и тёмной темой с сохранением выбора;
- предоставлять REST API для доступа к данным;
- при отсутствии координат организации пытаться геокодировать её по текстовому названию.

### 2.3. Нефункциональные требования

Из нефункциональных требований ключевыми являются производительность и покрытие геокодирования. Граф с 70 статьями должен отображаться без зависания браузера — это ограничение выбрано исходя из читаемости: при большем числе узлов граф перестаёт быть понятным. Покрытие геокодирования — не менее 75% публикаций. Приложение должно запускаться на Windows и Linux без изменения кода; ответы API сжиматься gzip при поддержке клиентом.

### 2.4. Технические ограничения

- Одновременно в графе отображается не более 70 публикаций.
- Список статей в интерфейсе ограничен 200 записями на одну страницу.
- Полные тексты публикаций не загружаются и не хранятся — только метаданные.
- Приложение работает локально; развёртывание на публичный сервер не предусмотрено в текущей версии.

**[Рисунок 1 — Общая архитектура системы: OpenAlex API → скрипт загрузки → PostgreSQL → геокодирование → серверный API → браузерный интерфейс]**

| Серверный API | `openalex_server.py`, `pg_config.py` | HTTP-сервер, REST-эндпоинты, gzip-сжатие |
| Интерфейс | `interface/VKR1.html`, `vkr1_app.js`, `vkr1_styles.css` | Карта, граф, фильтры, поиск похожих |


### 3.2. Обоснование выбора технологий

**Python** выбран для серверной части и скриптов. Стандартная библиотека содержит `http.server` и `json` — достаточно для HTTP-сервера без сторонних фреймворков. Из внешних зависимостей использованы только `psycopg2` [15] для работы с PostgreSQL и `ijson` [14] для потокового чтения JSON.

**PostgreSQL** [10] выбран потому, что между сущностями проекта (публикации, авторы, журналы, аффилиации) существуют чёткие реляционные связи. Для фасетной фильтрации нужны JOIN-запросы с несколькими условиями — именно это хорошо умеют реляционные СУБД. SQLite не рассматривался из-за ограниченной поддержки параллельных запросов.

**Plotly** [11] выбран для отображения географической карты (`scatter_geo`): встроенная поддержка проекций карты мира, интерактивность без дополнительного кода, интеграция в HTML-страницу через CDN.

Для **графа связей** выбрана ручная отрисовка в SVG [16] без внешних библиотек — без D3, без Cytoscape.js. Причина: нужна колоночная раскладка, при которой каждый тип узла занимает предсказуемую вертикальную позицию. Стандартные физические симуляции (force-directed layout) при 70+ узлах дают хаотичную и трудночитаемую картину. Колоночная раскладка детерминирована и остаётся читаемой при любом числе узлов.

**OpenAlex** [1] выбран вместо Semantic Scholar, Crossref или Scopus: сервис бесплатный и не требует регистрации; метаданные полные (авторы, аффилиации с идентификаторами, тематические классификаторы); cursor pagination обеспечивает надёжную выгрузку без дублирований; отдельный эндпоинт `/institutions` позволяет пакетно запрашивать координаты по идентификаторам.

Данные в системе проходят следующий путь:

## ГЛАВА IV. ЗАГРУЗКА ДАННЫХ ИЗ OPENALEX

### 4.1. Источник данных

Данные загружаются из OpenAlex [1] — открытого каталога научных работ организации OurResearch. Сервис бесплатный, регистрация не нужна, ограничение — не более 10 запросов в секунду.

### 4.2. Скрипт загрузки: import.py

Скрипт обращается к эндпоинту `/works` и постранично скачивает публикации: до 200 записей на страницу, до 50 страниц за запуск — итого не более 10 000 статей.

Для каждой публикации извлекается: название, год публикации, DOI; журнал (`primary_location.source.display_name`); авторы и их аффилиации (`authorships`); тематические классификаторы (`topics`) и ключевые слова (`keywords`).

Навигация между страницами реализована через **cursor pagination** — механизм, при котором каждый ответ API содержит токен `next_cursor` для получения следующей страницы. Это позволяет обходить большие наборы данных без пропусков и дублирований, что не гарантирует offset-based pagination при изменении набора данных между запросами.

Результат сохраняется в `article_data.json` в виде списка журналов, каждый из которых содержит массив статей. Пример структуры сохраняемого объекта приведён в приложении А.

При сбое соединения скрипт использует ранее сохранённый файл, не начиная загрузку заново.

## ГЛАВА V. БАЗА ДАННЫХ

### 5.1. Выбор СУБД

Для хранения данных выбрана PostgreSQL [10] — реляционная СУБД с открытым исходным кодом. Реляционная модель здесь естественна: один журнал содержит много статей, одна статья имеет много авторов, один автор может работать в нескольких организациях. Для фасетной фильтрации нужны JOIN-запросы — именно это является сильной стороной реляционных СУБД.

Настройки подключения хранятся в `pg_config.py` (см. приложение А). Параметр `client_encoding: utf8` обязателен при работе на Windows: без него PostgreSQL возвращает сообщения об ошибках в кодировке cp1251, что приводит к `UnicodeDecodeError` в Python. Все скрипты проекта импортируют единый конфигурационный файл, поэтому настройки меняются в одном месте.

### 5.2. Схема базы данных

База состоит из семи таблиц. ER-диаграмма с указанием типов полей, первичных и внешних ключей показана на рисунке 3.

**[Рисунок 3 — ER-диаграмма базы данных]**

| Таблица | Назначение | Ключевые поля (тип) |
|---|---|---|
| `journals` | Научные журналы | `journal_id` serial PK, `openalex_id` varchar, `name` text, `issn` varchar, `publisher` text |
| `publications` | Публикации | `publication_id` serial PK, `title` text, `doi` varchar UNIQUE, `publication_year` smallint, `abstract` text, `journal_id` int FK |
| `persons` | Авторы | `person_id` serial PK, `openalex_id` varchar UNIQUE, `full_name` text, `orcid` varchar |
| `affiliations` | Организации авторов с геокоординатами | `affiliation_id` serial PK, `person_id` int FK, `institution` text, `institution_id` varchar, `country` varchar, `latitude` real, `longitude` real |
| `publication_authors` | Связь публикация — автор | `publication_id` int FK, `person_id` int FK, `author_position` smallint |
| `publication_topics` | Тематические классификаторы | `id` serial PK, `publication_id` int FK, `topic_name` text, `score` real |
| `publication_keywords` | Ключевые слова | `id` serial PK, `publication_id` int FK, `keyword_name` text, `score` real |

**Связи:**

- `journals` → `publications`: один журнал — много публикаций (1:N);
- `publications` ↔ `persons`: многие публикации имеют многих авторов (N:M через `publication_authors`);
- `persons` → `affiliations`: один автор может работать в нескольких организациях (1:N);
- `publications` → `publication_topics`, `publication_keywords`: одна публикация — несколько тем и слов (1:N).

**Проектные решения.** Авторы вынесены в отдельную таблицу `persons`, а не хранятся строкой в публикации, потому что один автор участвует во многих статьях — денормализованное хранение привело бы к дублированию данных и невозможности построить граф авторских связей. Связь «публикация — автор» реализована через промежуточную таблицу `publication_authors`, а не через массив в PostgreSQL, поскольку нужно хранить позицию автора (`author_position`) и выполнять эффективные JOIN-запросы в обоих направлениях. Координаты организаций хранятся непосредственно в таблице `affiliations` в полях `latitude real` и `longitude real` — это позволяет запрашивать все публикации с координатами одним JOIN без дополнительной таблицы геопривязки.

Полный SQL-скрипт создания таблиц с индексами и ограничениями целостности вынесен в приложение Б.

### 5.3. Загрузка данных

Файл `article_data.json` весит более 200 МБ. Для потокового чтения без загрузки всего файла в память используется библиотека `ijson` [14] — она разбирает JSON объект за объектом. При вставке публикаций применяются savepoint-ы на случай конфликтов уникальных ключей: ситуации, когда два объекта OpenAlex ссылаются на один DOI, встречаются в реальных данных. Savepoint позволяет откатить только конфликтующую вставку, не прерывая транзакцию целиком. Листинг скрипта загрузки приведён в приложении А.

## ГЛАВА VI. ГЕОГРАФИЧЕСКАЯ ПРИВЯЗКА

### 6.1. Задача геокодирования

Геокодирование — это получение географических координат (широты и долготы) по названию или идентификатору организации. В OpenAlex координаты не идут вместе с публикациями; их нужно запрашивать отдельно.

Геокодирование проходит в два этапа, потому что не все аффилиации в базе устроены одинаково. Часть из них имеет `institution_id` — ссылку на запись в каталоге OpenAlex. Для таких можно запросить координаты напрямую. Остальные записаны только строкой названия — для них используется геокодер по тексту.

Алгоритм геокодирования показан на рисунке 5.

**[Рисунок 5 — Блок-схема геокодирования аффилиаций]**

### 6.2. Этап 1 — OpenAlex Institutions API

Скрипт `fetch_geo.py` собирает все уникальные `institution_id` из таблицы `affiliations` и запрашивает их батчами по 100 штук через эндпоинт `/institutions` [1]. OpenAlex возвращает JSON с полями `geo.latitude` и `geo.longitude` для каждого учреждения. Между батчами — пауза 0,5 секунды, чтобы не превысить лимит API. Результаты сохраняются в кэш-файл — при повторном запуске уже обработанные идентификаторы не запрашиваются заново.

Порядок обработки выбирается по приоритету: сначала организации, которые встречаются у авторов наибольшего числа публикаций без координат. Это позволяет максимально быстро увеличить покрытие карты.

**Результат первого этапа:** координаты получены для 7 822 из 9 994 публикаций (78%).

### 6.3. Этап 2 — геокодирование по строке названия

Для строковых аффилиаций без `institution_id` используется геокодер Photon [12] от Komoot — бесплатный сервис на основе данных OpenStreetMap.

Строки аффилиаций часто длинные и содержат лишнее — например, «Department of Physics, University of Tokyo, Japan». Скрипт применяет стратегию сокращения: пробует сначала полную строку, потом три последних части через запятую, потом две. Как только геокодер вернул результат — берётся первый вариант.

Важная деталь: Photon возвращает координаты в формате GeoJSON, где порядок — `[longitude, latitude]`, а не привычный `[latitude, longitude]`. При сохранении в базу координаты переставляются: широта берётся из второго элемента массива, долгота — из первого.

Исходно планировалось использовать Nominatim (основной геокодер OpenStreetMap), однако после нескольких прогонов сервис вернул HTTP 403 — IP был заблокирован за превышение допустимой частоты запросов. Переход на Photon решил проблему.

**Результат второго этапа:** геокодировано 229 из 257 строк аффилиаций, обновлено 410 записей. Итоговое покрытие: **8 077 из 9 994 публикаций (80,8%)** — выше заявленного порога 75%.

Оставшиеся 19,2% — аффилиации, записанные фрагментарной строкой без названия города или организации («Department of Physics»), по которой геокодер не может определить местоположение.

### 7.6. Поиск похожих статей

При клике на статью приложение перебирает все остальные статьи в текущей выборке и для каждой вычисляет балл сходства. Это происходит в браузере без запросов к серверу — все нужные данные уже загружены.

Балл сходства вычисляется по формуле:

**S = 4·n_а + 3·n_т + 2·n_к + 2·n_аф + 2·δ_ж**

где:
- n_а — число общих авторов;
- n_т — число общих тем;
- n_к — число общих ключевых слов;
- n_аф — число общих аффилиаций;
- δ_ж = 1, если публикации вышли в одном журнале; 0 иначе.

Статьи сортируются по убыванию балла. Те, у кого S = 0, в список не попадают.

Авторы получили наибольший вес, потому что один человек работает в одной предметной области и его статьи содержательно близки. Темы из OpenAlex — широкие классификаторы, их вес выше, чем у ключевых слов. Веса подобраны на реальных данных из базы.

Перед сравнением все строки (имена авторов, ключевые слова, названия организаций) приводятся к нижнему регистру и обрезаются пробелы по краям — без этого «MIT» и «mit» считались бы разными значениями.

## ЗАКЛЮЧЕНИЕ

В ходе выпускной квалификационной работы разработано веб-приложение для анализа и визуализации научных публикаций по метаданным из OpenAlex [1].

Выполнено следующее. Написан скрипт загрузки данных через cursor pagination, собравший **9 994 публикации** с полными метаданными. Спроектирована реляционная база данных PostgreSQL [10] из **7 таблиц** со связями, ограничениями целостности и каскадными удалениями; при загрузке применялись savepoint-ы для устойчивости к конфликтам уникальных ключей. Написан серверный API на Python [13] с gzip-сжатием [17] ответов. Геокодирование аффилиаций двумя методами — через OpenAlex Institutions API и через Photon [12] — дало итоговое покрытие **80,8% (8 077 из 9 994 публикаций)** при пороге 75%. Реализована интерактивная карта на Plotly [11] с поддержкой тёмной и светлой темы, граф связей с пятью режимами отображения в SVG [16] без внешних библиотек, алгоритм поиска похожих статей по взвешенному баллу из пяти признаков, браузерный интерфейс с фасетной фильтрацией.

Все четыре критерия, заданных в начале работы, выполнены:

| Критерий | Целевое значение | Фактический результат |
|---|---|---|
| Покрытие геокодирования | ≥ 75% | **80,8%** (8 077 из 9 994) |
| Граф без зависания при 70 статьях | выполнено | ✓ (requestAnimationFrame, ленивый расчёт) |
| Фасетные фильтры без пустых результатов | выполнено | ✓ (зависимые списки вариантов) |
| Алгоритм по ≥ 3 признакам | ≥ 3 признака | **5 признаков** (авторы, темы, ключевые слова, аффилиации, журнал) |

По сравнению с рассмотренными инструментами [2–5] система объединяет в одной браузерной среде без установки то, что в остальных решениях разнесено по разным продуктам: географическую карту с точными координатами организаций, граф связей с несколькими режимами, фасетную фильтрацию и алгоритм поиска похожих, не основанный только на цитированиях.

Возможные направления дальнейшего развития: реализация полнотекстового поиска по аннотациям, добавление экспорта графа в форматы VOSviewer [2] и Gephi [5], переход на серверный рендеринг графа для поддержки наборов свыше 10 000 публикаций.

## ПРИЛОЖЕНИЕ А. Пример структуры данных и листинги

### А.1. Пример структуры article_data.json

Файл `article_data.json` содержит список журналов; каждый журнал хранит массив статей. Каждая статья включает идентификатор OpenAlex, название, год, DOI, список авторств (имя автора + список организаций с идентификаторами), темы и ключевые слова.

### А.2. Конфигурация подключения к базе данных

Файл `pg_config.py` содержит словарь с параметрами: хост, порт, имя базы, пользователь, пароль и обязательный `client_encoding: utf8`. Последний параметр необходим при работе на Windows, где PostgreSQL по умолчанию возвращает сообщения об ошибках в кодировке cp1251.

### А.3. Листинг скрипта загрузки данных в базу

Скрипт `setup_pg_database.py` читает `article_data.json` через `ijson` (потоковый разбор), последовательно вставляет записи в таблицы `journals`, `publications`, `persons`, `affiliations`, `publication_authors`, `publication_topics`, `publication_keywords`. При конфликте по уникальному ключу (дубликат DOI) выполняется откат к savepoint без прерывания транзакции.

## ПРИЛОЖЕНИЕ Б. Схема базы данных (SQL)

Полный SQL-скрипт создания таблиц содержится в файле `database/db.sql`. Скрипт создаёт таблицы в порядке, учитывающем зависимости по внешним ключам: сначала `journals`, затем `publications` (ссылается на `journals`), затем `persons`, `affiliations` (ссылается на `persons`), затем три связующие таблицы. На всех внешних ключах установлено `ON DELETE CASCADE`. Индексы созданы по полям `publication_year`, `journal_id`, `institution_id`, `topic_name` для ускорения типичных запросов фасетной фильтрации.
