Преддипломная практика проходила в рамках выпускной квалификационной работы на тему «Визуализация науки на основе метаданных публикаций и журналов». Визуальные инструменты — карта и граф — позволяют увидеть научный ландшафт там, где раньше было просто большое количество записей.

## 3. ОПИСАНИЕ ВЫПОЛНЕННОЙ РАБОТЫ

### 3.1. Загрузка данных из OpenAlex

На первом этапе был изучен API OpenAlex — бесплатного каталога научных публикаций организации OurResearch. Для загрузки написан скрипт `scripts/import.py`, который обращается к эндпоинту `/works` и постранично скачивает публикации: до 200 записей на страницу.

Для навигации между страницами применяется **cursor pagination**: каждый ответ API содержит токен `next_cursor`, который используется в следующем запросе. Этот механизм исключает пропуски и дублирования при обходе больших наборов данных.

Для каждой публикации извлекаются:
- название, год, DOI;
- журнал;
- авторы и их аффилиации (организации);
- тематические классификаторы и ключевые слова.

Результат сохраняется в `article_data.json`. Если загрузка прерывается, скрипт использует уже сохранённый файл и продолжает работу. Итого загружено **9 994 публикации**.

### 3.2. Проектирование и наполнение базы данных

Для хранения данных выбрана PostgreSQL — реляционная СУБД с поддержкой сложных JOIN-запросов, необходимых для фильтрации. База содержит **7 таблиц**:

| Таблица | Назначение |
|---|---|
| `journals` | Научные журналы |
| `publications` | Публикации (название, год, DOI, аннотация) |
| `persons` | Авторы |
| `affiliations` | Организации авторов с координатами |
| `publication_authors` | Связь публикация ↔ автор (N:M) |
| `publication_topics` | Тематические классификаторы |
| `publication_keywords` | Ключевые слова |

Настройки подключения вынесены в отдельный файл `pg_config.py` с обязательным параметром `client_encoding: utf8` — без него на Windows PostgreSQL возвращает ошибки в кодировке cp1251, что приводит к сбоям в Python.

Поскольку файл данных весит более 200 МБ и не помещается в память целиком, для его чтения использована библиотека `ijson`, читающая JSON потоково — объект за объектом. При загрузке применялись savepoint-ы для обработки конфликтов: иногда два объекта OpenAlex ссылались на один DOI. Все 9 994 публикации загружены без ошибок.

### 3.3. Геокодирование организаций

Геокодирование — получение географических координат для организаций авторов — проходило в два этапа.

**Этап 1 — OpenAlex Institutions API.** Для организаций с идентификатором OpenAlex координаты запрашивались батчами по 100 ID через API учреждений. Между батчами — пауза 0,5 секунды. Результаты кэшировались в `geo_cache.json`. Покрытие по итогам: **78% публикаций**.

**Этап 2 — Photon (OpenStreetMap).** Для аффилиаций, записанных только строкой названия без идентификатора, использовался геокодер Photon от Komoot. Скрипт применяет стратегию сокращения строки: сначала пробует полное название, затем последние три части через запятую, затем две — пока не получит результат. Обрабатываются в первую очередь организации, которые встречаются у авторов наибольшего числа публикаций без координат.

Важная деталь: Photon возвращает координаты в формате GeoJSON с порядком `[longitude, latitude]`. При сохранении они переставляются в `[latitude, longitude]`.

Итоговое покрытие: **80,8% публикаций получили географическую привязку**.

### 3.4. Разработка серверного API

Сервер написан на Python с использованием стандартной библиотеки `http.server`. Он принимает запросы от браузера и возвращает данные из PostgreSQL.

| Эндпоинт | Описание |
|---|---|
| `GET /api/articles` | Список публикаций с авторами, темами, аффилиациями |
| `GET /api/article/{id}` | Детали публикации: аннотация, DOI |
| `GET /api/stats` | Счётчики по таблицам |
| `GET /api/data-tables` | Полные данные всех таблиц |

Ответы сжимаются gzip, если клиент поддерживает соответствующий заголовок. Это сократило объём передаваемых данных в 5–10 раз и устранило обрывы соединения при больших ответах.

### 3.5. Разработка веб-интерфейса

Интерфейс — одностраничное приложение (`interface/VKR1.html`) с тремя колонками:
- **Левая панель** — фасетные фильтры (год, журнал, автор, аффилиация), список статей, кнопки режимов;
- **Центральная область** — карта или граф;
- **Правая панель** — детали выбранной статьи, список похожих;
- **Нижняя секция** — данные таблиц базы.

**Фасетная фильтрация**: при выборе значения в одном фильтре остальные автоматически показывают только допустимые варианты с учётом текущего выбора. Это исключает комбинации, не дающие результатов.

**Тёмная тема**: все цвета заданы через CSS-переменные, переключение сохраняется в `localStorage` и применяется мгновенно.

**Карта** строится через библиотеку Plotly (`scatter_geo`). Каждая точка — аффилиация автора с известными координатами. Цвета суши, океана и границ подстраиваются под тему интерфейса.

Для обеспечения производительности при работе с 10 000 записей:
- тяжёлые операции вынесены в `requestAnimationFrame` — не блокируют интерфейс;
- при открытии страницы показываются демо-данные, реальные загружаются в фоне;
- подсчёт всех попарных связей статей (O(n²)) исключён из постоянного расчёта.

### 3.6. Граф связей

Граф рисуется в SVG-элементе прямо в браузере, без внешних библиотек. Данные для него берутся из уже загруженного списка статей — дополнительных запросов к серверу не требуется.

Из каждой статьи извлекаются: год, журнал, авторы, аффилиации — и строятся узлы и рёбра. Используется **колоночная раскладка**: каждый тип узла получает свою вертикальную колонку, узлы внутри распределяются равномерно по высоте. Рёбра рисуются как кривые Безье. Физической симуляции нет — граф предсказуем при любом числе узлов.

Доступно **5 режимов отображения**:
1. Полный граф — все типы узлов и связей;
2. Годы + журналы + статьи — хронология и журнальная принадлежность;
3. Авторы — кто написал что, соавторства;
4. Аффилиации — какие организации в каких работах;
5. Похожие статьи — тематически близкие публикации.

Одновременно отображается не более 70 статей — для читаемости.

### 3.7. Алгоритм поиска похожих статей

При клике на публикацию система перебирает все остальные статьи в текущем отфильтрованном наборе и для каждой считает балл сходства с выбранной.

Алгоритм учитывает 5 признаков с весами:

| Признак | Вес |
|---|---|
| Общие авторы | 4 |
| Общие темы | 3 |
| Общие ключевые слова | 2 |
| Общие аффилиации | 2 |
| Одинаковый журнал | +2 |

Авторы получили наибольший вес: один исследователь обычно работает в одной предметной области, и его статьи содержательно близки. Темы из OpenAlex — широкие классификаторы, их вес выше, чем у конкретных ключевых слов.

Перед сравнением все строки приводятся к нижнему регистру — иначе «MIT» и «mit» считались бы разными значениями. Результат отображается в правой панели как ранжированный список с объяснением совпадений, а также в режиме графа «Похожие статьи» в виде рёбер.

## 4. ТЕХНИЧЕСКИЕ ТРУДНОСТИ И ИХ РЕШЕНИЕ

| Проблема | Решение |
|---|---|
| Файл JSON 201 МБ — GitHub отклоняет файлы >100 МБ | Удалён из истории, заменён дампом базы данных |
| MemoryError при чтении 200 МБ JSON | Потоковое чтение через библиотеку `ijson` |
| Браузер обрывает соединение при большом JSON-ответе | Добавлено gzip-сжатие ответов сервера |
| Интерфейс зависает при 10 000 статей | `requestAnimationFrame`, ленивый рендеринг |
| Nominatim заблокировал IP (HTTP 403) | Переход на геокодер Photon от Komoot |
| Кодировка cp1251 на Windows | Явное указание `client_encoding: utf8` в pg_config.py |
| Конфликты уникальных ключей при загрузке | Savepoint-ы при вставке данных |
| Конфликты при слиянии git-веток | Разрешение через `git checkout --theirs` |
